Quote Check — App Map

A take-home guide to where things live. Quote Check reads a PC quote you were given and shows, part by part, whether each price is reasonable and why — or an honest "can't verify". A language model only reads the quote; plain code decides every verdict.

The main pieces

The screen

React + TypeScript in web/src/. Three steps — ① Upload, ② Confirm, ③ Results — held in App.tsx. Nothing is saved.

The server

FastAPI in server/app/main.py, two endpoints: /api/read and /api/check.

The verdict rules

server/app/verdict.py and matcher.py: the median of sample listings and a fixed +10% / −30% band. Pure functions.

Data and the model

Hand-made sample prices in server/data/prices.json. One OpenAI call in quote_reader.py turns a screenshot or text into part lines.

One action, end to end: "Check prices"

Solid blue outline: the kernel (price evidence). Dashed: an external service.

Reference route — three stops

A route to follow in your editor. Search for the name in each file; line numbers drift.

  1. web/src/App.tsx → handleCheck

    Pressing "Check prices" on ② sends the lines you confirmed to the server through checkPrices in web/src/api.ts, then moves to ③. A failure keeps you on ② with "Couldn't check prices. Try again."

  2. server/app/main.py → check_line

    For each line: match (matcher.py) finds the sample product, or says the name is too vague or not in the sample — that becomes Can't verify. Otherwise typical_price_cents takes the median listing and judge (verdict.py) applies the band. ask_seller writes the question from a fixed template; the model never writes verdict text.

    The rule itself 
    def judge(quoted_usd: float, typical_cents: Fraction) -> Verdict:
    quoted_cents = to_cents(quoted_usd)
    if quoted_cents * 100 > typical_cents * 110:
        return "worth_questioning"
    if quoted_cents * 100 < typical_cents * 70:
        return "unusually_low"
    return "reasonable"

    Whole cents and a Fraction median keep the edges exact: 10% above is still Reasonable.

  3. web/src/components/ResultsStep.tsx → ResultsStep

    One card per screen: the overview, each part (ResultCard.tsx, with "Show proof"), then each question in a message bubble. sellerMessage builds the text "Copy all 3" puts on the clipboard. The icon row above each card is PartIcons.tsx.

A practice to reuse

When it works on your machine but not on the user's device, make the test reproduce the device before trusting a fix.

On a phone (Android Chrome 155) the page went blank after "Read quote", while the automated walk in desktop Chrome 144 passed. The phone's error, sent to the server log, pointed at a scroll-to-top effect: newer Chrome returns a Promise from window.scrollTo, and an arrow function without braces handed it to React as a cleanup function. The walk was changed so scrollTo returns a Promise; it then failed on the old build and passed on the fixed one, and the phone confirmed the fix.

// web/src/App.tsx — braces, so the effect returns nothing
useEffect(() => {
  window.scrollTo({ top: 0 })
}, [step])

Recorded in devpost/checklist.md → Revisions ("Scroll-to-top effects now return nothing"). The same move helps on any project: when a bug shows up only for users, copy their condition into your own check, see the check fail, then see it pass.

Run it again

# once
cp .env.example .env            # then put OPENAI_API_KEY in .env
cd server && uv sync
cd ../web && npm install

# every time — two terminals
cd server && uv run uvicorn app.main:app --reload --port 8010
cd web && npm run dev           # open http://localhost:5173
